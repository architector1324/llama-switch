# Llama Switch

![](./ref-dark.png)

Лёгкий и современный веб-интерфейс для одновременной работы с локальными серверами инференса.

Llama Switch ставит один дашборд и один OpenAI-совместимый эндпоинт перед несколькими движками: [llama.cpp](https://github.com/ggerganov/llama.cpp) для текста, распознавания речи, приёма аудио с картинками на вход и decision-моделей, [stable-diffusion.cpp](https://github.com/leejet/stable-diffusion.cpp) для генерации изображений, [qwentts.cpp](https://github.com/ServeurpersoCom/qwentts.cpp) или [audio.cpp](https://github.com/0xShug0/audio.cpp) для синтеза речи и audio.cpp для распознавания речи и генерации музыки. Несколько моделей могут работать одновременно, каждая на своём порту и своих картах; с выключенным **Multi-model** всё работает по-старому, одна модель за раз.

## Возможности

- **Шесть типов моделей в одном конфиге**: секции `llm`, `sd`, `tts`, `stt`, `music` и `decision`, в интерфейсе они называются **Language**, **Image**, **Speech**, **Transcription**, **Music** и **Decision**.
- **Несколько моделей сразу**: с включённым **Multi-model** загрузка модели не трогает остальные, так что языковая, картиночная и голосовая могут работать вместе. Выключено - каждый запуск останавливает всё остальное.
- **Вкладка Running**: все запущенные модели, какого бы типа они ни были. Вкладка зелёная, пока загружена хотя бы одна модель, и красная, когда не загружено ничего.
- **Свой дашборд у каждой модели**: щёлкните по любой строке, запущенной или нет, и дашборд покажет эту модель. Любое изменение поля перезапускает её с новым значением; то, что выставлено у ещё не загруженной модели, и будет применено при **Load**.
- **Настройки модели**:
  - **GPU**: на какой карте работает модель, или на всех сразу. У картиночных моделей своя строка на каждый модуль (диффузия, текстовый энкодер, VAE); **Profile** оставляет то, что для этого модуля написано в конфиге.
  - **Context Window** (на один слот) и **Parallel Slots** для языковых и decision-моделей.
  - **Preserve Thinking** для языковых моделей, **Output Size** и **Hires Fix** для картиночных, **Max Frames** для речевых.
- **Reset и Reset All**: настройки модели или всех секций возвращаются к значениям по умолчанию. Как и любое изменение поля, сброс перезапускает то, к чему относится.
- **Память, как её сообщает движок**: память модели и контекста для языковых и decision-моделей, веса и вычислительный буфер для картиночных, с разбивкой по каждой карте и RAM. audio.cpp цифр памяти не печатает, поэтому у синтеза речи, распознавания и музыки на нём их нет.
- **Счётчики в реальном времени**, свои для каждого типа:
  - **Language:** скорость генерации (t/s), скорость обработки промпта (t/s), заполненность контекста, всего токенов.
  - **Image:** время шага, время последней картинки, прогресс по шагам, счётчик картинок.
  - **Speech:** скорость как кратность реальному времени, длина последнего клипа против времени его генерации, сгенерировано кадров, счётчик клипов.
  - **Decision:** время последнего решения, размер его промпта, обслужено запросов.
  - **Transcription** и **Music:** пока никаких.
- **Автопереключение из API**: запрос, в котором указана модель, сначала загружает её, и неважно, пришло имя в JSON-теле (чат, картинки, синтез речи) или в multipart-загрузке (транскрипции, редактирование картинок).
- **Клиент в терминале**: `llmsw run`, `list`, `ps` и `stop` на манер ollama: запуск модели любого типа с настройками дашборда во флагах и файлами, прикреплёнными по пути; что есть в конфиге и что запущено. Автодополнение для fish знает модели и флаги каждого типа.
- **Логи движка**: у каждой модели свой лог, а в заголовке панели написано, чей он.
- **Темы оформления**: встроенная поддержка тёмной и светлой темы.
- **Ссылка на WebUI**: открывает родной интерфейс работающего движка по его собственному адресу. Страницы движков запрашивают свои пути абсолютными, поэтому под префиксом здесь не живёт ни одна из них.
- **Горячая перезагрузка конфига**: с флагом `--watch` правки подхватываются без перезапуска.

## Требования

- **Go 1.22+**, только для сборки. На выходе один статический бинарь со встроенным дашбордом; для работы ему больше ничего не нужно.
- **llama-server**: бинарный файл из `llama.cpp`, доступный в `PATH` либо указанный полным путём в конфиге. Список карт в выборе GPU берётся из `llama-server --list-devices`, поэтому он нужен, даже если вы запускаете только другие движки.
- Опционально, только для тех секций, которыми пользуетесь: `sd-server` из `stable-diffusion.cpp`, `tts-server` из `qwentts.cpp`, `audiocpp-server` из `audio.cpp` (в их сборке он называется `audiocpp_server`).
- Опционально, для секции `stt`: `ffmpeg`. audio.cpp распознаёт только WAV, поэтому любая другая загрузка (mp3 от Open WebUI, webm из записи в браузере) сначала перекодируется в WAV 16 кГц, моно.
- Опционально: `vulkaninfo`. С ним у каждой карты в выборе GPU подписан PCI-адрес - единственное, чем различаются две одинаковые карты.

## Установка

1. **Клонируйте репозиторий:**
   ```bash
   git clone https://github.com/architector1324/llama-switch.git
   cd llama-switch
   ```

2. **Соберите бинарь:**
   ```bash
   cd src && CGO_ENABLED=0 go build -trimpath -ldflags "-s -w" -o ~/.local/bin/llmsw .
   ```
   Исходники, включая дашборд, лежат в `src/`; бинарь `llmsw` кладётся в `~/.local/bin`, где его ждёт systemd-юнит из репозитория, и запускается из любой директории.

## Настройка

Создайте файл конфига. systemd-юнит из репозитория читает `~/.config/llama-switch/config.yaml`; при запуске вручную бинарь берёт `config.yaml` из текущей директории, если `-f` не указывает другой. Модели раскладываются максимум по шести секциям; в каждой можно описать сколько угодно моделей, а неиспользуемые секции можно просто не писать.

Каждый профиль - одна строка запуска. Перед запуском сервер подставляет в неё плейсхолдеры:

| Плейсхолдер | Типы | Превращается в |
| --- | --- | --- |
| `${HOST}`, `${PORT}` | все | интерфейс и свободный порт для этой модели |
| `${CTX}` | `llm`, `decision` | контекст **на один слот**, умноженный на число слотов: то, что ждёт `-c` |
| `${PARALLEL}` | `llm`, `decision` | число слотов, для `--parallel` |
| `${DEVICES}` | все | выбранную карту в синтаксисе движка: `-dev Vulkan1` для llama.cpp, `--backend vulkan --device 1` для audio.cpp |
| `${DEVICES:<флаги>}` | все | то же, но при выборе **All GPUs** / **Profile** - `<флаги>`. Для `sd` строки GPU переназначают именно те роли, что перечислены в `<флагах>` |
| `${PRESERVE_THINK}` | `llm` | `--reasoning-preserve` или `--no-reasoning-preserve` |
| `${FRAMES}` | `tts` | потолок по аудиокадрам |
| `${WIDTH}`, `${HEIGHT}` | `sd` | выбранный Output Size |
| `${HIRES}`, `${HIRES:<флаги>}` | `sd` | при включённом Hires Fix - `--hires` или `<флаги>`; выключенном - ничего |

Короткие формы `$HOST`, `$PORT`, `$CTX`, `$PARALLEL`, `$FRAMES`, `$WIDTH`, `$HEIGHT` и `$PRESERVE_THINK` тоже работают.

**Пример `config.yaml`:**

```yaml
llm:
  # Модель с несколькими вариантами квантования
  qwen-3:
    q4_k_m: llama-server --parallel ${PARALLEL} ${DEVICES} --host ${HOST} --port ${PORT} --model /path/to/qwen3-instruct-q4_k_m.gguf -c ${CTX} -ngl 99
    q8_k_xl: llama-server --parallel ${PARALLEL} ${DEVICES} --host ${HOST} --port ${PORT} --model /path/to/qwen3-instruct-UD-Q8_K_XL.gguf -c ${CTX} -ngl 99

  # Мультимодальная модель, вход картинками и/или звуком (с mmproj)
  gemma-3:
    q4_k_m: llama-server --parallel ${PARALLEL} ${DEVICES} --host ${HOST} --port ${PORT} --model /path/to/gemma-3-it-q4_k_m.gguf --mmproj /path/to/gemma-3-it-mmproj.gguf -c ${CTX} -ngl 99

  # Распознавание речи на llama-server живёт здесь; на audio.cpp - в секции stt
  qwen3-asr:
    q8: llama-server --parallel ${PARALLEL} ${DEVICES} --host ${HOST} --port ${PORT} --model /path/to/Qwen3-ASR-1.7B-Q8_0.gguf --mmproj /path/to/mmproj-Qwen3-ASR-1.7B-Q8_0.gguf -c ${CTX} -ngl 99

sd:
  # Раскладка профиля: диффузия на одной карте, текстовый энкодер и VAE на другой
  z-image:
    q8_0: sd-server -l ${HOST} --listen-port ${PORT} --diffusion-model /path/to/z_image_turbo-Q8_0.gguf --llm /path/to/Qwen3-4B-Q8_0.gguf --vae /path/to/ae.safetensors ${DEVICES:--backend diffusion=Vulkan1,te=Vulkan0,vae=Vulkan0} -W ${WIDTH} -H ${HEIGHT} --steps 8 --cfg-scale 1.0 ${HIRES:--hires --hires-denoising-strength 0.5} -v

tts:
  qwen3-tts:
    q8: tts-server --host ${HOST} --port ${PORT} --model /path/to/qwen-talker-1.7b-base-Q8_0.gguf --codec /path/to/qwen-tokenizer-12hz-Q8_0.gguf --max-new ${FRAMES}

stt:
  # Распознавание речи на audio.cpp; загрузки не в WAV сначала проходят через ffmpeg
  nemotron-asr:
    f16: audiocpp-server --config /path/to/nemotron-asr.json --host ${HOST} --port ${PORT} ${DEVICES} --busy-timeout-ms 0

music:
  minimax-music3:
    q4: audiocpp-server --config /path/to/music.json --host ${HOST} --port ${PORT} ${DEVICES} --busy-timeout-ms 0

decision:
  # Отвечает на типизированные вопросы за один проход; эндпоинт /v1/systemone
  clef:
    q8_0: llama-server --parallel ${PARALLEL} ${DEVICES} --host ${HOST} --port ${PORT} --model /path/to/Clef-Flash-Q8_0.gguf -c ${CTX} -ngl 99
```

- `-ngl 99`: выгрузка слоёв на GPU (настройте под своё железо).
- `-c ${CTX}`, `--parallel ${PARALLEL}`: контекст и слоты, задаются для каждой модели в UI. Два слота по 8192 просят у движка 16384.
- `${DEVICES}`: уберите его из профиля, и эта модель перестанет слушаться выбора GPU.

**Квантование по умолчанию:** дефолтным считается **первый** вариант квантования в списке модели. Через OpenAI-совместимый API (`/v1/models`, `/v1/chat/completions`) он доступен под коротким id модели (например, `qwen-3`), а остальные получают суффикс `-<quant>` (например, `qwen-3-q8_k_xl`). Запрос короткого id загружает первый по списку вариант, поэтому ставьте предпочтительный квант первым в группе модели.

**Имена моделей общие для всех секций.** Если один и тот же ключ встретился в двух секциях, побеждает первая по порядку `llm`, `sd`, `tts`, `stt`, `music`, `decision`, а дубликат пропускается с записью в лог.

**Старые конфиги продолжают работать.** Конфиг без секций, где всё лежит под одним ключом `models:`, читается как секция `llm`; явная секция `llm:` всегда имеет приоритет над ним.

**Для цифр памяти нужен трассировочный лог.** llama.cpp печатает размеры буферов только на уровне логирования 4, поэтому языковые и decision-модели запускаются с `LLAMA_ARG_LOG_VERBOSITY=4`. Этот уровень шумнее всю работу модели, а не только загрузку: каждый запрос добавляет строки кэша промпта. Ещё простаивающая модель писала бы `all slots are idle` раз в секунду - эту одну строку панель отбрасывает.

## API

Запрос, в котором указана модель, идёт к экземпляру, который её обслуживает, и сначала загружает её, если она не запущена. Запрос без имени модели (чат-эндпоинтам оно нужно всегда) идёт к единственной запущенной модели этого типа: если таких нет - `503`, если их несколько - `409` с просьбой назвать нужную. Если указать модель другого типа, например картиночную в чат-эндпоинте, - `409` с адресом эндпоинта, который её обслуживает.

Запросы к движкам идут к ним напрямую и не смотрят на `http_proxy`, так что системный прокси не мешает.

| Эндпоинт | Секция |
| --- | --- |
| `/v1/models` | все секции; у каждой записи есть `type`, а в списке в стиле ollama ещё `kind` и `capabilities` |
| `/v1/chat/completions`, `/v1/completions`, `/v1/responses` | `llm` |
| `/v1/audio/transcriptions`, `/v1/audio/translations` | `stt`, если в запросе указана `stt`-модель или модель не указана, а `stt`-модель запущена; иначе `llm`, где это собственные ASR-эндпоинты `llama-server` |
| `/v1/images/*` (OpenAI), `/sdapi/v1/*` (AUTOMATIC1111), `/sdcpp/v1/*` (родной) | `sd` |
| `/v1/audio/speech`, `/v1/audio/voices` | `tts` |
| `/v1/tasks/*` | `music`, собственный эндпоинт генерации `audio.cpp` |
| `/v1/systemone` | `decision` |

Qwen3-ASR начинает транскрипт с заголовка `language <Язык><asr_text>`. Он вырезается и из ответов транскрипции, и из ответов чата, в стриме и без, так что клиент получает только текст.

Управление:

| Эндпоинт | Что делает |
| --- | --- |
| `GET /api/status[?model=]` | все запущенные экземпляры и запомненные настройки |
| `POST /api/start` | запустить модель с заданными настройками |
| `POST /api/stop[?model=]` | остановить одну модель или все |
| `POST /api/reset[?model=\|?kind=]` | вернуть настройки к умолчаниям и перезапустить то, к чему они относятся; без параметров - всё |
| `POST /api/multi` | `{"multi": true}` - держать несколько моделей, `false` - вытеснять при каждом запуске |
| `GET /api/logs[?model=]`, `GET /api/logs/owner[?model=]`, `POST /api/logs/clear[?model=]` | лог модели |
| `GET /api/devices` | карты, которые видит движок, с PCI-адресами |
| `GET /api/config` | конфиг, разложенный по секциям |

## Использование

1. **Запустите сервер:**
   ```bash
   llmsw serve --config config.yaml --watch
   ```

2. **Откройте дашборд:**
   Перейдите по адресу `http://localhost:11435` в браузере.

3. **Управление:**
   - Выберите вкладку секции, щёлкните по модели, выставьте ей GPU, контекст и остальное и нажмите **Load**.
   - Включите **Multi-model**, чтобы держать несколько моделей; щелчок по любой запущенной строке, здесь или на вкладке **Running**, переключает дашборд на неё.
   - Любое изменение поля перезапускает модель с ним; **Reset** возвращает модели значения по умолчанию, **Reset All** - всем.
   - Нажмите **Open WebUI**, чтобы открыть родной интерфейс работающего движка.
   - Нажмите **Unload** у модели или **Stop All**.

### Флаги сервера

`llmsw serve` принимает:

| Флаг | По умолчанию | Значение |
| --- | --- | --- |
| `-H`, `--host` | `localhost` | интерфейс для UI **и** для движков, которые он запускает |
| `-p`, `--port` | `11435` | порт UI (движкам каждый раз выдаётся свободный порт) |
| `-c`, `--ctx` | `4096` | размер контекста по умолчанию, на один слот |
| `-np`, `--parallel` | `1` | число слотов по умолчанию |
| `-f`, `--config` | `config.yaml` | путь к файлу конфига |
| `-w`, `--watch` | выкл | перечитывать конфиг при изменении файла |

### Из терминала

Кроме `serve`, бинарь умеет быть клиентом для работающего сервера, примерно как у ollama:

| Команда | Что делает |
| --- | --- |
| `llmsw run МОДЕЛЬ [ПРОМПТ]` | запускает модель любого типа; если она не запущена, сначала загружает её |
| `llmsw list [ТИП]`, `llmsw ls` | все модели из конфига с типом, квантом и состоянием; `ТИП` оставляет одну секцию |
| `llmsw ps [МОДЕЛЬ...]`, `llmsw status` | запущенные модели: состояние, память, карты, контекст и порт. С именами (как в `ps`) - то, что показывает о каждой дашборд: её настройки, счётчики её типа и память по картам, а память хоста - строкой RAM |
| `llmsw stop МОДЕЛЬ...`, `llmsw stop --all` | выгружает названные модели (имена как в `ps`) или все сразу; если хоть одна из названных не запущена, не останавливается ничего |
| `llmsw completion fish` | скрипт автодополнения для fish, [ниже](#автодополнение) |

Сервер они ищут по адресу из `LLMSW_HOST`, по умолчанию `localhost:11435`; подходит и просто `host:port`, и полный URL. Имена моделей - те же id, что отдаёт `/v1/models`, так что всё, что показывает `list`, можно передать в `run`.

`run` берёт вход из промпта или со стандартного входа и выдаёт один результат; текст из пайпа идёт первым, промпт - после него. Если нет ни того, ни другого, а вход - терминал, открывается сессия: `"""` открывает и закрывает многострочное сообщение, Ctrl+C останавливает текущий результат, `/bye` или Ctrl+D - выход. Что модель делает со входом, зависит от её типа:

| Тип | Вход | Результат |
| --- | --- | --- |
| `llm` | сообщение с картинками, аудио и видео, если в нём есть пути к ним | ответ, потоком; сессия помнит беседу, `/clear` её забывает |
| `sd` | промпт и картинки для правки, если они есть | PNG |
| `tts` | текст | WAV с озвучкой, сразу проигрывается |
| `music` | промпт | WAV с треком, сразу проигрывается |
| `stt` | записи, указанные в командной строке, аудио из пайпа или путь в каждом сообщении | расшифровка |
| `decision` | вопрос да/нет с состоянием из пайпа или состояние для вопросов из `--questions` | ответы |

```bash
llmsw run gemma4 "Скажи привет тремя словами"
llmsw run gemma4 photo.png "Что на картинке?"
git diff | llmsw run qwen3.6:35b --system "Ты пишешь сообщения коммитов." "Напиши одно для этого"
llmsw run z-image "рыжий кот на подоконнике" > cat.png
llmsw run mage-flow-edit cat.png "сделай кота чёрным"
llmsw run qwen3-tts --voice Kore "Привет!"
llmsw run qwen3-asr meeting.mp3
cat ticket.txt | llmsw run clef:9b "Is this urgent?"
```

Файлы прикрепляются по пути. Путь в промпте или в сообщении сессии - набранный, вставленный или перетащенный из файлового менеджера - вырезается из текста и уходит вместе с ним; в кавычках, с экранированными пробелами и как `file://` он работает так же.

- Языковая модель получает картинки, аудио и видео по этим путям, если их принимает её mmproj; если нет, об этом скажет llama-server. WAV, MP3 и FLAC он читает сам, остальное аудио сначала переводится в WAV через ffmpeg. Сессия держит файлы в беседе, а путь к несуществующему файлу остаётся частью вопроса.
- Картиночная модель рисует новую картинку по промпту или правит те, что ей дали: названные в сообщении и переданные через `--image`. Путь к несуществующей картинке - ошибка, а не промпт, которого никто не имел в виду.

Файлы ищутся только в промпте и в сообщениях. Текст из пайпа уходит как есть, поэтому `ls | llmsw run gemma4 "Какие из них фото?"` ничего не прикрепляет.

Картинки и аудио пишутся в файл из `-o`; без него - в стандартный вывод, если это не терминал, а иначе в новый файл в текущей директории с именем модели и временем. Аудио, сохранённое в терминале, проигрывается первым найденным из `pw-play`, `paplay`, `aplay` и `ffplay`; `--no-play` только сохраняет его. Decision-модель печатает в терминал таблицу, а в остальных случаях - весь JSON-ответ вместе с вероятностями. Файл `--questions` содержит объект `questions` запроса `/v1/systemone`, сам по себе или внутри `{"questions": ...}`.

Флаги, относящиеся к одному типу:

| Флаг | Тип | Что делает |
| --- | --- | --- |
| `--system ТЕКСТ` | `llm` | системный промпт; в сессии переживает `/clear` |
| `--hide-thinking` | `llm` | убирает размышления |
| `--voice ИМЯ` | `tts` | голос, один из тех, что отдаёт `/v1/audio/voices` |
| `--duration СЕКУНДЫ`, `--lyrics ТЕКСТ` | `music` | длина трека и текст песни |
| `--questions ФАЙЛ` | `decision` | вопросы, которые задавать |
| `--image ФАЙЛ`, `--mask ФАЙЛ` | `sd` | картинка для правки, можно несколько раз; какую её часть менять |
| `-o ФАЙЛ`, `--no-play` | `sd`, `tts`, `music` | куда писать результат; сохранить аудио без проигрывания |

Настройки дашборда - тоже флаги, каждый для тех типов, для которых его показывает дашборд. Если флаг задан, модель запускается с ним, как изменение поля на дашборде её перезапускает; незаданные настройки берутся у запущенного экземпляра, а модель, которая уже запущена именно так, не трогается:

| Флаг | Тип | Поле дашборда |
| --- | --- | --- |
| `--gpu КАРТА` | любой | **GPU**: карта, как её называет выбор GPU, несколько через запятую, или `all`. Для `sd` пары `роль=карта` задают **GPU per module**: `--gpu diffusion=Vulkan1,te=Vulkan0` |
| `--ctx N`, `--parallel N` | `llm`, `decision` | **Context Window** (на слот), **Parallel Slots** |
| `--preserve-thinking` | `llm` | **Preserve Thinking**; `--preserve-thinking=false` выключает |
| `--size ШxВ`, `--hires` | `sd` | **Output Size**, **Hires Fix** |
| `--frames N` | `tts` | **Max Frames** |
| `--multi` | любой | **Multi-model**, выставляется до загрузки модели; `--multi=false` выключает |

Флаг для другого типа - ошибка, а не молчаливый пропуск.

Размышления языковой модели показываются приглушённым цветом между `Thinking...` и `...done thinking.`, когда ответ идёт в терминал; `--hide-thinking` их убирает, как и вывод куда-либо ещё. Пока сервер работает, спиннер пишет, чего ждёт: `loading МОДЕЛЬ`, а для картинки `step 3/8`. Если модель грузится дольше минуты, которую ждёт сервер, `run` просто ждёт дальше.

`--verbose` после каждого результата печатает его цифры в stderr, так что в пайп попадает только результат. Для языковой модели это то, что сообщает llama-server, в том виде, как печатает ollama: число токенов промпта и ответа, время и скорость, попадания в кэш промпта и принятые черновые токены; load duration - всё остальное время запроса, то есть загрузка модели, если она не была запущена. Для остальных типов - общее время, а также размер картинки, длина клипа и скорость относительно реального времени или размер промпта у decision.

### Автодополнение

`llmsw completion fish` печатает скрипт автодополнения для fish. Ставится он один раз:

```fish
llmsw completion fish > ~/.config/fish/completions/llmsw.fish
```

По ходу набора скрипт спрашивает у самого бинаря, что подходит, через сервер из `LLMSW_HOST`, поэтому сам успевает за конфигом. Он предлагает:

- команды и модели из конфига с их типами;
- после модели - только флаги для её типа;
- карты сервера для `--gpu` и размеры с дашборда для `--size`;
- для `ps` и `stop` - запущенные модели;
- имена файлов там, где нужен файл: записи для `stt`, вложения для `llm` и `sd` и файлы, которые берут флаги.

### Как systemd-сервис

В репозитории лежит пользовательский юнит [llama-switch.service](llama-switch.service): он запускает `llmsw serve` из `~/.local/bin` на `~/.config/llama-switch/config.yaml` с `--watch`. Добавьте в его `ExecStart` нужные флаги (`--host 0.0.0.0`, чтобы дашборд был доступен с других машин), затем:

```bash
cp llama-switch.service ~/.config/systemd/user/
systemctl --user daemon-reload
systemctl --user enable --now llama-switch
```

Сообщения самого сервера, в том числе о перезагрузке конфига и командная строка каждого запуска, идут в журнал: `journalctl --user -u llama-switch -f`. То, что печатают движки, смотрите в **Upstream Logs** у каждой модели на дашборде.

### Микрофон

Всё раздаётся по обычному `http`. Браузер отдаёт микрофон только в защищённом контексте, а из адресов на обычном http таким считается один `localhost`, поэтому с телефона или ноутбука, заходящего по имени хоста или IP, элементы записи недоступны.

> Учтите, что `--watch` перечитывает конфиг, **останавливая все запущенные модели**. Не правьте конфиг, пока модель в процессе генерации.
