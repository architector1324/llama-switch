# Llama Switch

![](./ref-dark.png)

Лёгкий и современный веб-интерфейс для удобного переключения между локальными серверами инференса.

Llama Switch ставит один дашборд и один OpenAI-совместимый эндпоинт перед несколькими движками: [llama.cpp](https://github.com/ggerganov/llama.cpp) для текста, распознавания речи и приёма аудио с картинками на вход, [stable-diffusion.cpp](https://github.com/leejet/stable-diffusion.cpp) для генерации изображений, [qwentts.cpp](https://github.com/ServeurpersoCom/qwentts.cpp) для синтеза речи. Одновременно работает одна модель: загрузка следующей автоматически останавливает текущую.

## Возможности

- **Три типа моделей в одном конфиге**: секции `llm`, `sd` и `tts`, в интерфейсе они называются **Language**, **Image** и **Speech**.
- **Переключение в один клик**: автоматически останавливает текущую модель перед запуском новой.
- **Автопереключение из API**: запрос, в котором указана модель, сначала загружает её, и неважно, пришло имя в JSON-теле (чат, картинки, синтез речи) или в multipart-загрузке (транскрипции, редактирование картинок).
- **Дашборд реального времени**, свой для каждого типа:
  - **Language:** скорость генерации (t/s), скорость обработки промпта (t/s), заполненность контекста, всего токенов.
  - **Image:** время шага, время последней картинки, прогресс по шагам, счётчик картинок.
  - **Speech:** скорость как кратность реальному времени, длина последнего клипа против времени его генерации, сгенерировано кадров, счётчик клипов.
- **Настраиваемые лимиты**: размер контекста для `llm` и максимум кадров для `tts` задаются перед загрузкой модели и запоминаются отдельно для каждого типа.
- **Логи движка**: сырой вывод запущенного сервера прямо в интерфейсе.
- **Темы оформления**: встроенная поддержка тёмной и светлой темы.
- **Ссылка на WebUI**: открывает родной интерфейс работающего движка: страницу `llama-server`, страницу `sd-server` или страницу `tts-server`, переопубликованную по адресу `/tts/`.
- **HTTPS**: раздача по TLS, именно это делает микрофон доступным с другого устройства.
- **Горячая перезагрузка конфига**: с флагом `--watch` правки подхватываются без перезапуска.

## Требования

- **Python 3.8+** с пакетами `fastapi`, `uvicorn`, `pyyaml` и `httpx`.
- **llama-server**: бинарный файл из `llama.cpp`, доступный в `PATH` либо указанный полным путём в конфиге.
- Опционально, только для тех секций, которыми пользуетесь: `sd-server` из `stable-diffusion.cpp`, `tts-server` из `qwentts.cpp`.

## Установка

1. **Клонируйте репозиторий:**
   ```bash
   git clone https://github.com/your-username/llama-switch.git
   cd llama-switch
   ```

2. **Установите зависимости Python:**
   ```bash
   pip install fastapi uvicorn pyyaml httpx
   ```

## Настройка

Создайте файл `config.yaml` в корневой директории. Модели раскладываются максимум по трём секциям; в каждой можно описать сколько угодно моделей, а неиспользуемые секции можно просто не писать.

Используйте плейсхолдеры `${HOST}`, `${PORT}`, `${CTX}` и `${FRAMES}` в строке запуска, приложение подставит значения само. `${CTX}` задаёт размер контекста и имеет смысл только для `llm`; `${FRAMES}` задаёт потолок по аудиокадрам и имеет смысл только для `tts`. Короткие формы `$HOST`, `$PORT`, `$CTX` и `$FRAMES` тоже работают.

**Пример `config.yaml`:**

```yaml
llm:
  # Модель с несколькими вариантами квантования
  qwen-3:
    q4_k_m: llama-server --host ${HOST} --port ${PORT} --model /path/to/qwen3-instruct-q4_k_m.gguf -c ${CTX} -ngl 99
    q8_k_xl: llama-server --host ${HOST} --port ${PORT} --model /path/to/qwen3-instruct-UD-Q8_K_XL.gguf -c ${CTX} -ngl 99

  # Мультимодальная модель, вход картинками и/или звуком (с mmproj)
  gemma-3:
    q4_k_m: llama-server --host ${HOST} --port ${PORT} --model /path/to/gemma-3-it-q4_k_m.gguf --mmproj /path/to/gemma-3-it-mmproj.gguf -c ${CTX} -ngl 99

  # Распознавание речи тоже крутится на llama-server, поэтому живёт здесь же
  qwen3-asr:
    q8: llama-server --host ${HOST} --port ${PORT} --model /path/to/Qwen3-ASR-1.7B-Q8_0.gguf --mmproj /path/to/mmproj-Qwen3-ASR-1.7B-Q8_0.gguf -c ${CTX} -ngl 99

sd:
  z-image:
    q8_0: sd-server -l ${HOST} --listen-port ${PORT} --diffusion-model /path/to/z_image_turbo-Q8_0.gguf --vae /path/to/ae.safetensors --steps 8 --cfg-scale 1.0 -v

tts:
  qwen3-tts:
    q8: tts-server --host ${HOST} --port ${PORT} --model /path/to/qwen-talker-1.7b-base-Q8_0.gguf --codec /path/to/qwen-tokenizer-12hz-Q8_0.gguf --max-new ${FRAMES}
```

- `-ngl 99`: выгрузка слоёв на GPU (настройте под своё железо).
- `-c ${CTX}`: размер контекстного окна (меняется через UI).
- `--max-new ${FRAMES}`: потолок длины клипа (меняется через UI).

**Квантование по умолчанию:** дефолтным считается **первый** вариант квантования в списке модели. Через OpenAI-совместимый API (`/v1/models`, `/v1/chat/completions`, …) он доступен под коротким id модели (например, `qwen-3`), а остальные получают суффикс `-<quant>` (например, `qwen-3-q8_k_xl`). Запрос короткого id загружает первый по списку вариант, поэтому ставьте предпочтительный квант первым в группе модели.

**Имена моделей общие для всех секций.** Если один и тот же ключ встретился в двух секциях, побеждает первая в порядке `llm` → `sd` → `tts`, а дубликат пропускается с записью в лог.

**Старые конфиги продолжают работать.** Конфиг без секций, где всё лежит под одним ключом `models:`, читается как секция `llm`; явная секция `llm:` всегда имеет приоритет над ним.

## API

Любой запрос обслуживает та модель, которая сейчас загружена. Запрос, в котором указана модель, сначала загружает её, так что чат-клиент, клиент картинок и клиент речи каждый подтягивает своё, не трогая дашборд. Запрос в чужую секцию без имени модели получит `409` с указанием, какой тип загружен сейчас.

| Эндпоинт | Секция |
| --- | --- |
| `/v1/models` | `llm` (только текстовые модели, чтобы чат-клиентам не предлагались движки картинок) |
| `/v1/chat/completions`, `/v1/completions`, `/v1/responses` | `llm` |
| `/v1/audio/transcriptions`, `/v1/audio/translations` | `llm`, это собственные ASR-эндпоинты `llama-server` |
| `/v1/images/*` (OpenAI), `/sdapi/v1/*` (AUTOMATIC1111), `/sdcpp/v1/*` (родной) | `sd` |
| `/v1/audio/speech`, `/v1/audio/voices` | `tts` |
| `/tts/*` | `tts`, собственная страница `tts-server`, переопубликованная на этом же origin |
| `/api/config`, `/api/status`, `/api/logs`, `/api/start`, `/api/stop` | управление |

## Использование

1. **Запустите сервер:**
   ```bash
   python server.py --config config.yaml --watch
   ```

2. **Откройте дашборд:**
   Перейдите по адресу `http://localhost:11435` в браузере.

3. **Управление:**
   - Выберите модель в левом списке и нажмите **Load**.
   - При необходимости измените **Context Window** (языковые модели) или **Max Frames** (речевые).
   - Нажмите **Open WebUI**, чтобы открыть родной интерфейс работающего движка.
   - Нажмите **Stop** или загрузите другую модель, чтобы завершить текущую сессию.

### Аргументы командной строки

| Флаг | По умолчанию | Значение |
| --- | --- | --- |
| `-H`, `--host` | `localhost` | интерфейс для UI **и** для движков, которые он запускает |
| `-p`, `--port` | `11435` | порт UI (движкам каждый раз выдаётся свободный порт) |
| `-c`, `--ctx` | `4096` | размер контекста по умолчанию |
| `-f`, `--config` | `config.yaml` | путь к файлу конфига |
| `-w`, `--watch` | выкл | перечитывать конфиг при изменении файла |
| `--tls-cert`, `--tls-key` | выкл | PEM-сертификат и ключ; если заданы оба, UI переходит на `https` |

### HTTPS и микрофон

Браузер отдаёт микрофон только в защищённом контексте. `localhost` считается защищённым и по обычному http, а любой другой адрес уже нет, включая телефон или ноутбук, заходящий по имени хоста или IP, и элементы записи там просто исчезают. Передайте `--tls-cert` и `--tls-key`, чтобы раздавать по `https`, и позаботьтесь, чтобы сертификат был подписан удостоверяющим центром, которому доверяет то устройство: самоподписанный сертификат отвергается сразу, а кнопки "всё равно перейти" недостаточно, защищённый контекст от этого не возвращается.

> Учтите, что `--watch` перечитывает конфиг, **останавливая всё запущенное**. Не правьте конфиг, пока модель в процессе генерации.
